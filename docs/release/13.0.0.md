# AetherShell 13.0.0 preparation

## Rust function signature refactoring, 2026-10-02

Refactor_change_signature(source, signature), refactor_add_parameter(source,
parameter, position?) and refactor_remove_parameter(source, parameter) now edit
exactly one supplied Rust free function with a body and return Rust source.
Change_signature retains the function name/visibility and replaces the supplied
signature; token-identical replacements reject. Add_parameter inserts a typed
identifier parameter at a zero-based index through the existing count, defaulting
to append. Remove_parameter requires an existing identifier, with raw identifiers
normalized consistently for lookup and duplicate binding checks. Inputs require
plain identifiers with optional mut and at most 64 parameters; receivers,
variadics, destructuring/ref/subpatterns, duplicates and missing bindings reject.

Dropping bindings, including through signature replacement, requires a
conservative scope-insensitive visitor check. Any matching body identifier rejects,
including field names and shadowed local bindings. Macros, attributes except
literal documentation, nested items and verbatim syntax also reject rather than
assuming that a parameter is unused. This covers implicit format-string captures
without evaluating macro expansions. The transformations do not resolve symbols,
imports or types, evaluate cfg, rewrite call sites, infer argument defaults or
modify body expressions. Callers apply the source and perform compiler/call-site
checks; type/qualifier/generic changes can require further body edits.

Visibility, function attributes, documentation and body/literal tokens are
retained. Source is emitted with token formatting: ordinary comments and layout
are discarded, and documentation comments become doc attributes. Output is
reparsed as one Rust function before return. Limits: 64 KiB/256 raw ASCII
punctuation characters for source, 16 KiB/128 punctuation for replacement
signatures or typed parameters, 256 bytes/32 punctuation for a removal identifier,
and 1 MiB output. Raw punctuation limits include comments and strings. Wrong
shapes, malformed syntax, unsupported patterns or pipeline input return coded
errors. All three operations remain direct-only and Pure, with no files or
compiler/subprocess execution in their implementation.

## Coverage and test outcome reports, 2026-10-02

Test_coverage(report) now summarizes LCOV 1.x text into {files, lines, functions,
branches}. Each metric contains found/hit Ints and a percent Float, or null when
no locations are present. File summaries sort by literal SF path. Repeated source
records merge covered locations by union, so aggregate percentages use distinct
locations rather than averaging file percentages or double-counting overlapping
reports. TN, SF, FN/FNDA, DA with optional checksum, BRDA and the six summary
records are supported. Branch '-' counts as not hit. Complete end_of_record
boundaries, matching function names and consistent supplied summary counts are
required. Duplicate data within a record, conflicting supplied line checksums or
function locations across records, unknown extensions and malformed numbers reject.
This summarizes supplied instrumentation output; it does not collect coverage,
open source files or launch a coverage tool. Modern LCOV extensions are outside
this LCOV 1.x contract. Limits are 1 MiB, 25000 lines, 64 KiB per line, 1024 source
records, 10000 data entries and 4096-byte names. Counts fit nonnegative Int and
line numbers are positive. Zero-location metrics have a null percentage.

Test_passing(report), test_failing(report) and test_skipped(report) now return
passed/failed/ignored results from completed Rust libtest JSON execution reports.
Each row contains a 1-based suite index, name, status, optional stdout/message/
reason Strings and optional exec_time Float; absent fields are null. Output sorts
by suite and name. Suite boundaries, test event sequencing, completion of every
declared test and exact summary counts are validated before any result returns.
Timeout notifications are nonterminal. Ignored outcomes may omit a start event;
filtered-out test identities are not available and are not inferred. Optional
post-suite merged-doctest timing reports are checked. Duplicate JSON keys/test
events, unknown fields/events, wrong types/durations, incomplete/fail-fast suites,
discovery/benchmark and Cargo compiler JSON reports reject. Limits are 1 MiB,
25000 lines, 64 KiB per line, 128 suites, 10000 completed tests and 4096-byte names.
Libtest JSON reporting remains an unstable Rust test-harness format. No last-run
cache or implicit test execution is introduced. All four operations remain Pure,
require an explicit report String and reject pipeline input. Files compose with
ordinary guarded file builtins:

```ae

test_failing(cat("tests.jsonl")) | map(fn(r) => r.name)
```

Other witnesses cover Unicode/captured diagnostics, ordering across suites,

## Native Ed25519 signatures, 2026-10-02

Crypto_sign(private_key, message) now returns an Ed25519 signature Record with
algorithm, public_key and signature fields. Crypto_verify_signature(public_key,
message, signature) returns a Bool: well-shaped invalid signatures return false;
malformed input returns a coded error. Messages are UTF-8 Strings or byte Int
Arrays, bounded to 1 MiB. Keys/signatures use canonical padded standard Base64
for raw 32/64-byte values. Signing accepts one unencrypted Ed25519 PKCS#8 v2
PRIVATE KEY PEM envelope, at most 4096 bytes, and checks embedded public-key
consistency. PKCS#8 v1, RSA, P-256, certificates, key files and prehash variants
are outside these signature contracts.

Crypto_generate_key("ed25519") uses operating-system randomness through ring
on native platforms and returns PKCS#8 v2 PEM. Bit sizes are RSA-only. Existing
Unix OpenSSL RSA/P-256 generation remains; its non-Unix implementation gap is
still open. No key registry, files or subprocesses are used by the Ed25519 path.
Signing/verification remain Pure, and key generation retains its conservative
WriteLocal classification. AETHER_FIPS refuses this backend with E_POLICY_DENY
because it is not FIPS validated. Decoded private-key PEM/DER buffers are
zeroized; caller Strings and library-internal key storage have no wiping guarantee.

Ring 0.17.14 was already in Cargo.lock through TLS and is now an explicit,
optional native dependency. The lockfile only adds the root dependency edge;
no package versions changed. Known-answer data comes from
[RFC 8032 section 7.1](https://www.rfc-editor.org/rfc/rfc8032.html#section-7.1).
The project and 13.0.0 release remain incomplete; no version bump or publication
is included. Signature inventory remains 604/1171 implementations and 729/1437
names because these three declarations already existed.

## Typed snapshot comparison and Rust test generation, 2026-10-02

Test_snapshot compares supplied actual and baseline values and returns matched,
mismatches, truncated and structured differences. It preserves Int/Float type
distinctions, treats finite signed-zero Floats as equal, and rejects opaque or
nonfinite values. Differences use escaped JSON Pointer paths and added/removed/
changed kinds relative to the baseline. Record keys are sorted; array indices
retain their order. Absence is distinguished from a present Null by the kind.
All differences are counted, with the first 128 returned. Both inputs are
validated first. Combined limits are depth 32, 10000 nodes and 1 MiB scalar/key
bytes (eight per numeric/Null/Bool value); record keys are at most 256 bytes.
Baseline loading and persistence compose with the existing file/parse builtins.
The comparison itself is Pure and does not write files.

supplied function path and explicit argument/expected expression Strings.

execute or typecheck them or infer test oracles. Stable case names begin at
case_000 inside __ae_generated_tests. The module imports super::* and permits
explicit crate:: function paths. Limits are 1..128 cases, 64 arguments per case,
16 KiB per expression, 64 KiB total expression text, 128 raw ASCII punctuation
characters per expression including comments/strings, and 1 MiB output. Function
paths have a 256-byte/32-punctuation bound. Unknown fields, invalid syntax and
pipeline input reject. The returned source is embedded beside the code under
test and compiled/run separately. Generation remains Pure.

## Code search and public API documentation, 2026-10-02

Search_duplicates parses an explicit Rust source corpus and groups exact
normalized free-function clones, including inline modules. Comparison ignores
function names, outer attributes/visibility, comments and formatting, while
retaining parameters, types, qualifiers, generics, literal contents and bodies.
It returns only groups with multiple occurrences. Impl methods, imports and
macro expansion are outside this contract; conditional compilation is not
resolved and ambiguous duplicate function paths fail.

Search_similar accepts a single-function Rust query and ranks corpus functions
using Jaccard similarity of five-Unicode-scalar shingles of normalized syntax.
Results include document, function and score, ordered by descending score then
location. This is an explicit syntax-text metric, without alpha-renaming or
semantic-equivalence claims. Both source searches accept arrays of exactly
{name, source} records with unique nonempty document names. Each source is at
most 64 KiB and 256 raw ASCII punctuation characters, counting comments/strings;
corpora are at most 128 documents, 1 MiB total source and 256 free functions.

Search_semantic performs exact cosine nearest-neighbor search over embeddings
supplied by the caller in a common model/space. It does not produce embeddings
from source. Query vectors and corpus {name, embedding} records require equal
dimensions 1..4096, finite numeric components and nonzero vector norms. Scale normalization keeps
finite extreme/subnormal components usable. Results include negative scores,
are sorted by descending score then name, and validate every candidate before
returning. Corpus limits are 1024 entries and 1048576 compared components.
Both ranked searches accept limit 1..100, default 10.

Docs_api extracts top-level explicitly public Rust functions, structs, enums,
unions, traits, aliases, constants and statics into structured records with
name, kind, declaration and literal documentation. Function bodies are omitted
from their declaration; other kinds retain complete syntactic definitions.
Restricted/private items are excluded. This source-only frontend uses the
existing [Syn 2 parser](https://docs.rs/syn/2.0.117/syn/fn.parse_file.html), without
module/impl traversal, effective visibility/type resolution or HTML generation.
It uses the same per-source bounds. All four operations retain Pure effects,
reject pipeline input and never read files or execute analyzed source.

## Native TCP socket lifecycle, 2026-10-02

Net_connect and net_listen now create real TCP streams and return opaque,
process-local handles. Net_listen binds a literal IP and accepts one connection,
then drops its listener. Accepted streams explicitly return to blocking mode
before applying timeouts, accounting for [Windows socket inheritance](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-accept). Both accept port 1..65535 and an optional timeout of
1..10000 milliseconds (default 1000); the timeout also applies to later I/O.
Hostnames must be resolved separately, avoiding an unbounded DNS lookup during
connection setup. There are at most 128 retained handles, released by net_close
or process exit. Failed opens do not retain a handle. Concurrent opens check the
limit again at registration and drop excess streams.

Net_send accepts a UTF-8 String or Array of byte Ints 0..255, at most 1 MiB,
writes under a total deadline and returns the byte count. A failed send may
already have transmitted a prefix; callers must not blindly retry. Net_recv
performs one bounded read and returns {bytes: Array<Int>, eof: Bool}; TCP has no
message boundaries. A zero-byte read is EOF; a timeout is E_IO. Socket waits use
the smaller of the socket timeout and the remaining evaluation deadline. An
already expired evaluation deadline refuses I/O with E_BUDGET_EXCEEDED. Net_close shuts
down both directions and invalidates the handle; a closed flag and I/O waits of at most 50 milliseconds let pending reads/writes
observe closure without an unbounded mutex wait, including Windows reads that
do not promptly wake on shutdown of a cloned descriptor. Unknown/closed handles are E_BAD_STATE.
Concurrent send/read calls on one handle refuse as busy instead of blocking on
an unbounded mutex wait. Handles must be closed explicitly in long-lived hosts.

Every operation retains its Network classification and guards the actual peer;
listening guards both the bind address and accepted peer. A changed allowlist
can deny operations on an existing handle, including closure, until policy
permits that peer again. Accepted connections are dropped if the peer isdenied,
before application data is read. Transactions refuse because TCP effects and
receive cursors cannot be rolled back. Direct-only declarations reject discarded
pipeline input and malformed arguments. No placeholder success values remain
in these five builtins. Native Linux/macOS validation remains open.

## Implementation scope and first working replacements, 2026-10-02

The user selected implementation of all unsupported builtins. This supersedes
prior release-scope decisions to retain placeholder operations. The completion
plan now tracks actual functionality independently from signature coverage, with
a source candidate inventory separating placeholders from platform and rollback
constraints. No safety or policy guard is waived by this scope change.

Docs_types and docs_signatures now parse Rust source with syn instead of refusing.
Docs_types returns top-level struct/enum/union/trait/type-alias name, kind and
normalized definition records. Docs_signatures returns top-level free-function
name, normalized signature and async flag, including syntactic generics, return
types and where clauses. Results sort by name. Comments/string contents are not
mistaken for declarations and source is never executed. These are syntactic Rust
source-unit extractors, not file readers, macro expanders, nested module/impl
traversers or semantic type resolvers. Inputs are limited to 1 MiB and a
conservative 128 raw ASCII punctuation characters including comments and strings;
callers must use smaller source units when exceeding that complexity budget.
Invalid syntax and call shapes carry E_BAD_ARG; budget refusals are coded. Existing
Pure classifications are retained. Native-only optional syn/quote dependencies
use versions already present in the lockfile. Their generated outputs are
runtime documentation, not automatically authored builtin contracts.

Cron_list now uses a noninteractive Windows PowerShell query without profiles,
with terminating errors, explicit UTF-8 output, string State conversion and an
explicit JSON array. The parser requires complete nonempty string name/state/path
records; scalar JSON, empty stdout and incomplete records refuse with E_BAD_STATE.
Unix sets LC_ALL=C for crontab -l and accepts an absent table only for exit 1,
empty stdout and a specific single-line no-crontab diagnostic. Other failed exits
carry E_TOOL_FAILED. Successful Unix output excludes comments and environment
assignments, handles repeated whitespace and known @ schedules, and preserves
command text. It does not interpret environment variables or semantically
validate cron expressions. Supported syntax follows the
[crontab manual](https://manpages.ubuntu.com/manpages/jammy/man5/crontab.5.html).
Unknown special schedules or incomplete lines refuse instead of yielding partial
results. Native Unix command execution remains to validate on Unix.

Machine-dependent scheduler examples now invoke cron_list/at_list directly so
their results can be checked against the declared Array type. The initial
cron_list example incorrectly returned typeof(...) as a String; the discriminating

## Draft release notes

Builtin dispatch and ontology discovery now share more source-reviewed
argument contracts. Aliases of a declared implementation inherit its contract;
explicit declarations retain precedence. Calls with surplus or invalid arguments
can now fail with `E_BAD_ARG` where earlier versions silently discarded them.
This compatibility change warrants the selected major version.

The migration also fixes integer product overflow, swallowed `sort_by` key
errors, corrupted UTF-8 URL decoding, extraction that dropped the final email
or phone token, malformed JSON indexes selecting element zero, and Unicode
field previews that could panic. AgenticBinary refuses out-of-range byte codes
and overflowing payload lengths. UUID and random byte/string generation now run
in process; string generation handles Unicode and large character sets without
short results or an infinite rejection loop. Random sizes are bounded to
1,048,576 bytes or characters per call.

The earlier latency and throughput work is included in this release line.
Its measurements and methodology are recorded in
[`perf-2026-09-29-followup.md`](../../benches/agentic/results/perf-2026-09-29-followup.md).

command failures. The workflow verifies the requested version against Cargo.toml
before creating a public release. Registry publication still depends on each
registry's credential preflight.
