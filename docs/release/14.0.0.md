# AetherShell 14.0.0 preparation

## Release notes (draft for approval, 2026-10-23)

This section is the user-facing summary. The dated sections below it are the
preparation journal it was drawn from, newest first; where they disagree, the
newer section and CHANGELOG.md's `[Unreleased]` entry are current.

14.0.0 is a major release because calls that used to be quietly accepted now
fail. Every dispatched builtin carries a declared signature, and the dispatcher
holds calls to it: surplus or mistyped arguments, and pipeline input a builtin
does not take, are refused with `E_BAD_ARG` before anything runs. Builtins that
used to report success without doing the work now say so with a coded error.

### Breaking changes

**Calls are checked against their declarations.**

- Surplus arguments, wrong types and unwanted pipeline input are `E_BAD_ARG`.
  Before, `journal_clear("a")` ignored its argument and cleared the whole
  journal.
- Optional arguments no longer fall back to a default when they are malformed.
  In `fs_chmod`, the string `"0"` used to mean 0644; it now means mode 0, and a
  malformed mode is refused. A malformed `fs_chown` group is refused instead of
  being read as the owner.
- A pipeline stage's input goes only to that stage. A failing stage stops the
  pipeline with an error that names its index and builtin.

**Fake successes are now errors.** These used to answer as if they had
worked:

- `sso_auth` minted a token for any input. It is now `E_UNIMPLEMENTED` and
  mints nothing, so `sso_validate` answers `valid: false`.
- `finetune_start`, `job_submit`, the `cloud_*` instance builtins,
  `remote_exec`, `repl_serve`/`repl_connect`/`repl_broadcast`,
  `workspace_sync`, `plugin_load`, `marketplace_install` and
  `marketplace_update` reported work that nothing did.
- `compliance_check` and `compliance_report` called every standard compliant,
  and `audit_verify` called an empty log valid.
- `agent_with_mcp` reported a run that hit its step limit as completed; it is
  now `E_BUDGET_EXCEEDED`.
- `web_fetch`, `web_get`, `web_scrape`, `web_download` and `web_upload` fail on
  HTTP 4xx and 5xx. `web_download` of a 404 used to answer `true`.

**Agent-mode policy.** Each of these refuses with `E_POLICY_DENY` or asks for
approval:

- **Network:** egress needs approval unless `AETHER_NET_ALLOW` names the host
  (`*` restores the old behaviour). `ai_backends` charges, and in agent mode
  asks approval for, each endpoint it probes.
- **Clipboard:** `clipboard_get`, `clipboard_get_image` and
  `clipboard_history` read nothing unless `AETHER_SECRETS=allow` or
  `AETHER_POLICY=permissive`.
- **Undo and redo:** `undo`, `rewind`, `session_undo` and `session_redo` leave
  a recorded file outside the workspace jail alone. The step stays in the
  journal for a human-mode rewind.
- **Mode variables:** `set_env`, `env_set` and `env_unset` cannot change
  `AETHER_MODE`, `AETHER_APPROVE_ALL` or `AETHER_POLICY` from agent mode.
- **Commands that imply agent mode:** `ae mcp stdio`, `ae agent execute` and
  `ae agent interactive` now do, as `agent serve` and `mcp serve` already did.
- **Reclassified effects:** many builtins changed effect class, which decides
  when agent mode asks.
  - `rsync_sync` is Destructive.
  - `helm_install`, `helm_upgrade`, `uv_pip` and `test_watch` are Exec.
  - Undo, redo, `journal_clear` and `session_end` are WriteLocal.
  - The full list is in CHANGELOG.md.

**Renamed or reshaped results.**

| Builtin | 12.x | 14.0.0 |
|---|---|---|
| `proc_kill` | `true` / `false` | `{pid, signal, sent: true}`, or a coded error |
| `net_latency` | Int | Float (average round trip) |
| `nanda_quorum` | `total_agents` | `electorate` |
| `monitor_sockets` (Windows) | `foreign_address` | `peer_address`, as on every OS |
| `pkg_list` | `status`, `arch` fields; `rc` packages | `{name, version}` for installed packages |
| `proc_list` memory (Unix) | %MEM | bytes, as on Windows |
| `from_json`, JSON readers | JSON `null` as the string `"null"` | `null` |
| `grep` | substring | POSIX basic regular expression |
| `npm`/`pnpm`/`yarn` failure | record with `exit_code` | `E_TOOL_FAILED` with the stderr tail |
| `docker_logs` / k8s logs | all output | last 1,000 / 200 lines by default |

**Argument shapes.**

| 12.x | 14.0.0 |
|---|---|
| `docker_run("alpine", "echo hi")` | `docker_run("alpine", ["echo", "hi"])`; likewise `docker_exec`, the podman twins and `k8s_exec` |
| `tmux_new(name, cmd)` | `tmux_new(name)`, then `tmux_send` |
| `age_keygen()` returned the key | an output file is required, and no key is returned |
| `git_checkout("src/app.rs")` restored the file | the name is read as a revision only |
| `zip_create`, `scp_download`, `age`, `gpg`, `xz`, `zstd` overwrote outputs | an existing output is `E_BAD_STATE` |

**Error codes.**

- `E_DECRYPT_UNAUTHENTICATED` is folded into `E_DECRYPT_FAILED` (exit 65).
- `E_CRYPTO_FAILED` (exit 70) and `E_FIPS_DISALLOWED` (exit 77) are new.
- `E_OS_DENIED` (exit 77) is new: the operating system refused (file
  permissions, another user's or a protected process, a privilege not held).
  These were `E_POLICY_DENY`, which now means only the shell's own policy.
  Migration: `catch e { if e.error.code == "E_POLICY_DENY" ... }` written for
  an unreadable file or a foreign process tests `"E_OS_DENIED"` instead.
- `apply` refuses a plan of more than 10,000 ops (`E_BUDGET_EXCEEDED`).
- A tool stopped at its deadline is `E_BUDGET_EXCEEDED`.
- An uncaught `throw`, or a failing `assert` used as a statement, ends the
  program with exit 1.

**Removed.**

- The `ask` alias of `ai` was advertised but never dispatched. Call `ai`.
- The fallbacks that quietly used another tool are gone: rg to grep, fd to
  find, and yq to a JSON-only evaluator. A missing tool is `E_TOOL_MISSING`.

**Library and SDK.**

- The Python SDK's `Agent.run` and `Swarm.run` build the same call as the
  `agent` and `swarm` builtins, and raise `ValueError` for options those cannot
  honour.
- In the Rust API, `DQNAgent.step` and `MultiAgentRL.step` return `Result`.

### Migration

- A script that passed extra arguments, or piped into a builtin that ignored the
  pipe, now gets `E_BAD_ARG`. The message names the parameter and prints the
  signature, and `ae agent schema` lists every declaration.
- **Agents that use the network:** set `AETHER_NET_ALLOW` to the hosts they
  need.
- **Agents that read the clipboard:** set `AETHER_SECRETS=allow`, or do it in
  human mode.
- **Modifying a SQLite database:** use `db_sqlite_exec`. `sql`, `sqlite_query`
  and `db_sqlite_query` are read-only.
- **Legacy password hashes:** Windows SHA-256 hex hashes and Unix SHA-crypt
  (`$5$`, `$6$`) hashes verify, but only outside `AETHER_FIPS`, and should be
  rehashed after a successful verify. New hashes are Argon2id (PBKDF2 under
  `AETHER_FIPS`).
- **Python SDK callers:** catch `ValueError` from `Agent.run` and `Swarm.run`.

### New in 14.0.0

- `ae -b` runs the ordinary POSIX subset in-process: 32 of 32 byte-identical to
  bash on E6, and 32 of 32 on a held-out corpus. Anything else runs through the
  effect gate, never `bash -c`.
- **Data access:**
  - SQL over typed values and files: `sql`, `sql_value` and a bundled SQLite.
  - `open()` parses JSON, JSONL, TOML, YAML and CSV, and `.field` row syntax
    works in pipeline stages.
- **Agent tooling:** `ae --explain` and `explain_effects(code)` report a call's
  effect class and agent decision without running it.
- **Native builtins:**
  - Ed25519 signing and verification.
  - Argon2id password hashing (PBKDF2 under `AETHER_FIPS`).
  - TCP sockets with handles.
  - Filesystem watch.
  - A one-exchange `web_websocket`.
- **Real scheduling:** `cron_*` and `at_*` have working backends.
- **Linux system administration:** accounts, groups, ACLs, mounts, services,
  `sudo_exec` and apt. Verified as root in a disposable Debian 13.
- **Package listing:** `pkg_list` covers apt, pacman, rpm (dnf/yum), Homebrew
  and Windows Add/Remove Programs.
- **Windows:** `proc_env`, `proc_cwd`, `proc_suspend` and `proc_resume`; RSA/EC
  keys and certificate inspection through `openssl`.
- **Linux desktop:** clipboard types and images (X11 and Wayland), and
  `gui_screenshot_window` (X11).
- **Rust refactoring and navigation:** rename, extract function or variable,
  inline, move to file, change signature, definitions, references and callers.
- **Evaluator speed:** in four paired Windows rounds against `570bff8`, module
  calls ran 3.65x faster and two-argument `reduce` 2.27x. Workloads with no gain
  are listed in `benches/agentic/results/perf-2026-09-29-followup.md`. A Linux
  rerun of the final code reproduced both, at 4.56x and 1.91x
  (`benches/agentic/results/perf-2026-10-27.md`).

### Supported platforms

- **Linux and Windows:** the full workspace suite passes on both, each test
  binary under a memory cap: 264 binaries at b547789.
  - Linux system-administration and desktop backends are verified only in a
    disposable Debian distro.
  - The Windows service, account, group, scheduled-task and winget backends
    are verified with real changes only on a disposable GitHub runner.
- **macOS:** the workspace suite (`cargo test --workspace --features native`)
  passes on GitHub's `macos-26-arm64` image, and the x86_64 and aarch64 Apple
  builds succeed. Its clipboard, screenshot, `libc++`, process-environment and
  service paths are untested or unimplemented.
- **WASM:** the wasm32 library builds without default features. Its behaviour in
  a browser is not exercised.
- **Rust:** 1.88 is the MSRV, checked with and without default features. CI
  runs Clippy and the `local_inference` library tests with the `candle` and
  `onnx` features; neither loads a real model there.

### Known limitations

- `web_xpath` is not implemented. Use `web_scrape`, which matches tag names
  only.
- The hyphenated PowerShell-style names (`sort-object`, `where-object`,
  `get-content`, `get-files`) cannot be written in the language, so they have
  no declarations.
- **Windows:** clipboard images and window capture are `E_UNIMPLEMENTED`, and
  so are the Linux system-administration builtins.
- **Homebrew:** `pkg_list` has run only against parser fixtures.
- **`crypto_cert_verify`:** reads a missing trust store as `false`, because
  openssl's exit status does not tell the two apart.
- **Key generation:** `ssh_keygen`, `openssl_genrsa` and `age_keygen` write
  private keys unencrypted.
- **Processes:** a deadline kills a tool's direct child only, so processes
  that child started can outlive it.
- **Output shown unredacted:**
  - `proc_env` shows other processes' secrets.
  - `env_vars` redacts by variable name only, so a password inside
    `DATABASE_URL` is shown.
- **Not measured with a live model:** the E7 agentic benchmark.
- **Not checked on real hardware:** battery, GPU, sensor and CPU-frequency
  readings.

## Release procedure, artifacts and recovery (for approval)

The repository has no Actions secrets. The workflow builds and attaches the
binaries, but every registry publish job is skipped (`publish-preflight` finds
no `CARGO_REGISTRY_TOKEN`, `NPM_TOKEN` or `PYPI_TRUSTED_PUBLISHING`). Every
crates.io version so far went up by hand. Check each step against the registry
or the release page itself; a green run does not show that anything was
published.

**Before the tag, on the release commit:**

1. Rerun formatting, the full workspace tests on Windows and Linux (each binary
   under a memory cap), Clippy and the MSRV checks.
2. Check that `ae --version` prints 14.0.0 and that `py -3.12
   scripts/release_version.py 14.0.0` passes.
3. Fill in the date on the CHANGELOG's `## [14.0.0]` heading.

**Tag (needs explicit approval).** `scripts/release.ps1 -Version 14.0.0`
pushes `v14.0.0`. `release.yml` then runs these jobs:

1. **`create-release`** only resolves and checks the version.
2. **`build-binaries`** builds six archives:
   - x86_64 and aarch64 `unknown-linux-gnu`;
   - x86_64 `unknown-linux-musl`;
   - x86_64 and aarch64 `apple-darwin`;
   - `x86_64-pc-windows-msvc`, as a zip.
3. **`build-wasm`** builds `aethershell-wasm-14.0.0.tar.gz`.
4. **`build-linux-packages`** builds the `.deb` and the `.rpm`.
5. **`publish-release`** runs once all of those have passed. It creates the
   GitHub release, not as a draft, with all nine assets and the generated
   notes, and fails if fewer than nine arrived. If a build fails, no release
   exists until the failed job is re-run. (Until 2026-10-28 the release was
   published first, and its assets appeared as each build finished.)
6. **`homebrew-digest`** prints the source tarball's sha256 in the job summary.
   No tap push is configured.

**Expected assets.** Nine, named like v12.0.2's:

- `aethershell-14.0.0-<target>.tar.gz`, one for each of the five Unix targets;
- `aethershell-14.0.0-x86_64-pc-windows-msvc.zip`;
- `aethershell-wasm-14.0.0.tar.gz`;
- `aethershell_14.0.0-1_amd64.deb`;
- `aethershell-14.0.0-1.x86_64.rpm`.

Check the list on the release page after every job has finished.

**By hand, after the assets are complete** (each needs explicit approval):

1. Publish to crates.io: `cargo publish --features native`, then the LSP from
   `crates/aethershell-lsp`. The LSP needs the root crate on the index first.
   Verify both at `https://crates.io/api/v1/crates/<name>`.
2. Update `Formula/aethershell.rb`: the tag URL, plus the sha256 that
   `homebrew-digest` printed. Recompute that sha256 from the downloaded archive.
   Users tap this repository by URL (`brew tap nervosys/aethershell https://github.com/nervosys/AetherShell`),
   so the formula on master is what they get.
3. The SDK and the editor extensions version independently and are not part
   of this release.
4. Download every asset and smoke-test it on Windows, Linux and macOS:
   - `ae --version`;
   - a typed pipeline;
   - `ae agent serve` and its `/health`.

**Recovery.**

- **Bad tag, nothing published to a registry yet:**
  1. Delete the GitHub release.
  2. Run `git push --delete origin v14.0.0`, then delete the local tag.
  3. Fix the problem and tag again.
- **A missing or broken asset:** rerun that job, or attach the asset by hand
  with `gh release upload v14.0.0 <file> --clobber`. While the release is
  incomplete, mark it as a prerelease, or say so in its notes.
- **A bad crates.io upload:** a version cannot be deleted or reused.
  1. Yank it: `cargo yank --version 14.0.0 aethershell`, and the same for the
     LSP.
  2. Release 14.0.1 with the fix.
  3. Do not move the tag.
- **A wrong Homebrew sha256:** fix the formula from the real archive. It only
  takes effect for users once the tap exists.

## Scope decisions and the agent-mode clipboard gate, 2026-10-22

- **Agent mode does not read the clipboard**: clipboard_get, clipboard_get_image
  and clipboard_history are E_POLICY_DENY, nothing read, unless
  AETHER_SECRETS=allow (the existing opt-in for clear secret reads) or
  AETHER_POLICY=permissive. A password copied from a password manager has no
  shape for redaction to recognise. Argument errors still come first, and
  clipboard_types, which reads no contents, is not gated. Tested on Windows and
  Linux, where no call reaches a clipboard.
- **Linux text clipboard with no display.** clipboard_get and clipboard_set ran
  xclip with no display, which failed as E_TOOL_FAILED ("Can't open display").
  They are E_NO_UI first now, and E_UNIMPLEMENTED under Wayland with no X
  display, since xclip and xsel are X11 tools. Found by the new gate test.
- **wget_download** stays Network: a transaction must refuse it, since traffic
  cannot be rolled back. Its partial-file cleanup goes through remove_partial,
  like the other tool runners, so tests/write_evidence.rs passes again with
  its allowlist still at four entries.
- **A corrupt bzip2, xz or zstd file** stays `false` from archive_test, as a
  corrupt zip, tar or gz is, rather than E_TOOL_FAILED.
- **No new crates for 14.0.0.** web_xpath stays E_UNIMPLEMENTED: the XPath
  crate is unmaintained and parses XML only, while web pages are HTML. Windows
  clipboard images and window capture stay E_UNIMPLEMENTED, because they could
  not be verified here without a real desktop. Certificates and legacy
  decryption already run through openssl on every OS.

## Windows backends for process and openssl builtins; web_curl deadline, 2026-10-22

- **proc_env and proc_cwd read another process on Windows** (d07a8e2), through
  sysinfo, refreshed for that one pid. Windows hands back an empty environment
  and no directory for a protected or another user's process; that is
  E_OS_DENIED, never `{}` or `""`. cmd's hidden per-drive `=C:` entries are
  not variables and are skipped. On macOS, proc_env reads another process through the same sysinfo path
  (sysctl KERN_PROCARGS2), tested on a GitHub macOS runner against a child
  with a marker variable.
  Verified against a child started with a marker variable and a temp directory.
- **crypto_cert_info, crypto_cert_verify, RSA/EC crypto_generate_key and the
  opt-in legacy CBC decrypt run on Windows** (35aefa5). They already ran the
  `openssl` CLI; the Unix-only gate is removed. Without `openssl` on PATH each is
  E_TOOL_MISSING. Git for Windows ships one (OpenSSL 3.5), which the test uses
  when PATH has none. Legacy plaintext came back byte-exact through Git's
  openssl on Windows. Key generation writes no file; the PEM is returned.
- **web_curl** (330bd04) runs through run_tree: curl's own `--max-time` is 30 s,
  and at 45 s the shell kills curl's process tree and answers
  E_BUDGET_EXCEEDED. Before, it trusted curl's timer and joined its reader
  threads without a bound.
- **proc_suspend and proc_resume work on Windows** (aa62ee4). A PowerShell
  P/Invoke opens the process with PROCESS_SUSPEND_RESUME and calls ntdll's
  NtSuspendProcess or NtResumeProcess; the script prints one coded line, which
  is all Rust reads. Access denied is E_POLICY_DENY. Verified with a child
  whose counter file stops advancing while suspended and resumes after.
- **clipboard_types lists formats on Linux** (6e5c40f): X11 through
  `xclip -o -t TARGETS` (xsel as a fallback, which can only tell text), and
  Wayland through `wl-paste --list-types`. Targets map to text, image, files
  and audio, as on Windows. An empty clipboard is `[]`; no display is E_NO_UI.
  Verified under Xvfb in ae-disposable (empty, text, PNG image, no display).
  Under WSL, Xvfb's socket file never appears in WSLg's /tmp/.X11-unix, so the
  test also accepts the abstract socket (7b65b16). macOS still refuses.
- **web_websocket is implemented** (38da136) as one bounded exchange: connect
  (ws or wss), send, collect until the server closes, max_messages (default
  100, at most 1000) or timeout_secs (default 10, at most 120), close. Returns
  {messages, closed_by_server, timed_out}. Over 8 MiB is E_BUDGET_EXCEEDED.
  tungstenite 0.24 became a direct dependency; it was already built for axum,
  and its TLS feature links only rustls and webpki-roots that reqwest already
  builds, so no package was added to the lockfile. Setting the read deadline
  through a `try_clone` handle did not bound reads on Windows (a silent server
  held a 1 s call for 20 s); it is now set on the socket tungstenite holds.
  Tested against loopback servers: echo, close, binary, silent, over 8 MiB and
  refused connection.
- **clipboard_get_image and clipboard_set_image work on Linux** (X11 through
  xclip, Wayland through wl-clipboard): {mime, bytes, base64} out, an image
  file in. No image is E_NOT_FOUND; 32 MiB is the limit. The setter does not
  use run_tree, whose process-group kill would kill the tool's selection
  holder. Verified under Xvfb, including that the image survives the call.
- **gui_screenshot_window captures one window on Linux X11**: xwininfo finds
  the window whose title is exactly the argument, ImageMagick `import` captures
  it to stdout, and the shell checks it is a PNG and writes the file after the
  write guard, so `import` never interprets the path. A missing window is
  E_NOT_FOUND, no display E_NO_UI, Wayland and other OSes E_UNIMPLEMENTED.
  Verified under Xvfb with an xmessage window.
- **pkg_list works on Windows**: the Add/Remove Programs entries (64-bit and
  32-bit machine keys and the current user's, without system components or
  updates) as {name, version}; version is Null when a program records none.
  Checked against reg.exe, a reader with its own parser.
- The library without default features, and so the wasm32 web build, had not
  compiled since import/export landed (4ba43bc): src/module_loader.rs was not
  gated on `native` but uses the evaluator and the guard, which are. It is now
  gated; `cargo check --lib --no-default-features` and the same check for
  wasm32-unknown-unknown pass, and clippy is clean for both.
- The probe deadline was raised from 10 s to 30 s (5484da3); see the next
  section.

Verified on Windows and Linux (ae-disposable): lib, declared_signatures,
proc_tranche_contracts, proc_env_cwd_windows, crypto_openssl_windows,
os_branch_contracts, text_file_contracts, crypto_fail_closed,
crypto_authenticated, remaining_bounds_contracts, stdin_deadlock_contracts,
web_tranche_contracts and nettools_tranche_contracts pass; clippy is clean on
both.

## Deadlines for builtins.rs process probes, 2026-10-21

Every process builtins.rs starts now has a deadline, except where a person is
expected to answer. bounded_cmd_output (e25f643) runs a Command through
output_with_timeout: past its deadline the whole process tree is killed, and output
over 64 MiB is refused. 246 `.output()` calls were converted (8c4738c, 188374b):
version, `which`, `uname` and status probes get 30 s (PROBE_DEADLINE_SECS); tool
queries and actions 120 s; git fetch, pull and push 120 s (NETWORK_DEADLINE_SECS);
archive extraction, package verification and key generation 900 s. gui_powershell
and proc_tool take the deadline for all their callers.

Observable effects:
- A tool that hangs is now E_BUDGET_EXCEEDED after its deadline. Previously the call
  waited forever. spawn_error maps a timeout to E_BUDGET_EXCEEDED, so it is no longer
  reported as a failure to start (E_TOOL_FAILED).
- A probe that treated a failure to start as "not available" (hypervisor and
  platform detection, among others) treats a timeout the same way.
- Output over 64 MiB from these calls is refused as a budget error.
- The probe deadline was first 10 s. Under a parallel test run on Windows, six
  powershell-backed process readers exceeded it (cold `powershell` starts), so it
  was raised to 30 s (5484da3). It bounds a hung probe, not a slow one.

Left unbounded on purpose: gui_dialog_message, gui_dialog_input, gui_dialog_file_open,
gui_dialog_file_save, gui_dialog_folder, gui_color_picker and the Windows
read_terminal_password prompt. Each waits for a person. The `.status()` calls that
inherit the terminal (run_editor, devtool_attach, lazygit_open, stty) are also left
unbounded. tests/probe_deadline_contracts.rs fails if a new `.output()` appears in
any other function. It was checked by planting one in env_python, which it reported
at its line.

Verified on Windows and Linux (ae-disposable): lib, declared_signatures (30/30),
probe_deadline_contracts, guard_enforcement, effect_ratchet, platform_detection,
platform_tranche_contracts, remaining_bounds_contracts and structured_codes_contracts
pass, and clippy is clean on both. Linux clippy found three needless `mut` bindings
in Linux-only branches, which Windows cannot compile. platform_lib_version re-coded
a pkg-config timeout as E_TOOL_MISSING; both were fixed in b7822db. The macOS
branches (sw_vers, sysctl, xcrun, ioreg) are not compiled anywhere locally.

## Process runners, stdin deadlocks and pipeline input, 2026-10-21

Six commits, 2a0d298 to 4d7756d, changed how pipeline input reaches a stage, how
pipeline progress is reported, how bounded runs end, and which runners have
deadlines. The user-visible changes are listed first.

**Pipeline input.** A stage's input is now given to that stage's own call only.
Previously `"hello" | slice(1, len("hello"))` also piped "hello" into `len`, which
refused the call, so lib/string.ae's `capitalize` failed (2a0d298). Pipelines run
one stage at a time through one runner, shared by the streaming and non-streaming
paths. A failing step stops the pipeline with an error that names its index and
builtin. The streaming pipeline in agent_api used to emit a progress event for each
step before any step ran; those events were simulated. An event is now sent after
its step completes (65e388c). Events are still delivered when the pipeline ends,
not as they happen, because create_sse_response collects them first.
execute_cross_platform had no callers and was deleted, with translate_command and
translate_args, which only it used (65e388c).

**Bounded runs.** builtins::run_bounded, linux_diagnostics and tool_runs share
run_tree, and the other bounded call sites in 4d7756d use run_tree or run_tree_cmd.
At its deadline a run kills the whole process tree. On Unix the child leads its own
process group and the group is killed. On Windows taskkill /T runs first, bounded to
10 s (bea0f5a). Reader threads are never joined, so a grandchild holding a pipe
cannot hold the call past its deadline. Observable effects:
- A bounded-run child runs in its own process group, so a terminal Ctrl-C no longer
  reaches it directly.
- After a normal exit, a pipe still open after a 2 s grace is abandoned, and on Unix
  its group is killed. An abandoned pipe is reported as `pipes_abandoned`, not as
  truncation. The `_truncated` flags now mean only that output went past its Keep
  bound (cbe7c8d). Before this, a command that finished while a helper it started
  still held stdout failed in tool_text with "printed more than N bytes".
- On Windows, grandchildren that outlive a normally-exiting child cannot be found,
  and they keep running.

**External tools** (ExternalToolRegistry::execute, 4d7756d). A timeout is a coded
E_BUDGET_EXCEEDED error, where it used to be a success: false result. The child gets
null stdin, not the terminal's. Stderr is dropped when capture is off and kept as a
tail when it is on. Stdout is capped at 16 MiB, and output over the cap is a coded
budget error, not silent truncation. The watchdog thread, which signalled a PID that
might have been reused, is gone.

**Agent execute_step** (4d7756d) runs through run_tree_cmd. Before, its deadline was
checked only between blocking reads, so a silent child never reached it. A silent
child is now killed at the deadline. Its timeout and oversized stdout are coded
budget errors. It keeps a 64 KiB stderr tail.

**Other runners with deadlines** (4d7756d). safety::output_with_timeout is
reimplemented on run_tree_cmd with its signature unchanged. Output past 64 MiB is a
coded budget error carried in the io::Error, and spawn_error passes it through.
kubectl_run runs through run_tree: stdout is head-capped and stderr keeps a tail.

**Stdin deadlocks** (82cb3d6). Three runners wrote a child's stdin synchronously
before draining its stdout. A payload larger than the pipe buffer blocked the parent
on stdin while the child blocked on its full stdout pipe. They were the legacy
openssl decrypt, the scheduler's tool runner (crontab, at, atrm, schtasks and
PowerShell), and the account tools' spawn helper. All three now go through run_tree,
which writes stdin on its own thread, and they have deadlines: 30 s for openssl,
crontab, at, atrm and schtasks, and 60 s for PowerShell and the account tools. Output
caps are 64 MiB for legacy plaintext and 16 MiB for the other two. A deadline hit or
output past its cap is a coded budget error. Output is never truncated silently.

tests/pipe_input_scope.rs (2a0d298), tests/stream_pipeline_honesty.rs (65e388c),

## Code search and public API documentation, 2026-10-02

Search_duplicates parses an explicit Rust source corpus and groups exact
normalized free-function clones, including inline modules. Comparison ignores
function names, outer attributes/visibility, comments and formatting, while
retaining parameters, types, qualifiers, generics, literal contents and bodies.
It returns only groups with multiple occurrences. Impl methods, imports and
macro expansion are outside this contract; conditional compilation is not
resolved and ambiguous duplicate function paths fail.

Search_similar accepts a single-function Rust query and ranks corpus functions
using Jaccard similarity of five-Unicode-scalar shingles of normalized syntax.
Results include document, function and score, ordered by descending score then
location. This is an explicit syntax-text metric, without alpha-renaming or
semantic-equivalence claims. Both source searches accept arrays of exactly
{name, source} records with unique nonempty document names. Each source is at
most 64 KiB and 256 raw ASCII punctuation characters, counting comments/strings;
corpora are at most 128 documents, 1 MiB total source and 256 free functions.

Search_semantic performs exact cosine nearest-neighbor search over embeddings
supplied by the caller in a common model/space. It does not produce embeddings
from source. Query vectors and corpus {name, embedding} records require equal
dimensions 1..4096, finite numeric components and nonzero vector norms. Scale normalization keeps
finite extreme/subnormal components usable. Results include negative scores,
are sorted by descending score then name, and validate every candidate before
returning. Corpus limits are 1024 entries and 1048576 compared components.
Both ranked searches accept limit 1..100, default 10.

Docs_api extracts top-level explicitly public Rust functions, structs, enums,
unions, traits, aliases, constants and statics into structured records with
name, kind, declaration and literal documentation. Function bodies are omitted
from their declaration; other kinds retain complete syntactic definitions.
Restricted/private items are excluded. This source-only frontend uses the
existing [Syn 2 parser](https://docs.rs/syn/2.0.117/syn/fn.parse_file.html), without

It uses the same per-source bounds. All four operations retain Pure effects,
reject pipeline input and never read files or execute analyzed source.

## Native TCP socket lifecycle, 2026-10-02

Net_connect and net_listen now create real TCP streams and return opaque,
process-local handles. Net_listen binds a literal IP and accepts one connection,
then drops its listener. Accepted streams explicitly return to blocking mode
before applying timeouts, accounting for [Windows socket inheritance](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-accept). Both accept port 1..65535 and an optional timeout of
1..10000 milliseconds (default 1000); the timeout also applies to later I/O.
Hostnames must be resolved separately, avoiding an unbounded DNS lookup during
connection setup. There are at most 128 retained handles, released by net_close
or process exit. Failed opens do not retain a handle. Concurrent opens check the
limit again at registration and drop excess streams.

Net_send accepts a UTF-8 String or Array of byte Ints 0..255, at most 1 MiB,
writes under a total deadline and returns the byte count. A failed send may
already have transmitted a prefix; callers must not blindly retry. Net_recv
performs one bounded read and returns {bytes: Array<Int>, eof: Bool}; TCP has no
message boundaries. A zero-byte read is EOF; a timeout is E_IO. Socket waits use
the smaller of the socket timeout and the remaining evaluation deadline. An
already expired evaluation deadline refuses I/O with E_BUDGET_EXCEEDED. Net_close shuts
down both directions and invalidates the handle; a closed flag and I/O waits of at most 50 milliseconds let pending reads/writes
observe closure without an unbounded mutex wait, including Windows reads that
do not promptly wake on shutdown of a cloned descriptor. Unknown/closed handles are E_BAD_STATE.
Concurrent send/read calls on one handle refuse as busy instead of blocking on
an unbounded mutex wait. Handles must be closed explicitly in long-lived hosts.

Every operation retains its Network classification and guards the actual peer;
listening guards both the bind address and accepted peer. A changed allowlist
can deny operations on an existing handle, including closure, until policy
permits that peer again. Accepted connections are dropped if the peer isdenied,
before application data is read. Transactions refuse because TCP effects and
receive cursors cannot be rolled back. Direct-only declarations reject discarded
pipeline input and malformed arguments. No placeholder success values remain
in these five builtins. Native Linux/macOS validation remains open.
