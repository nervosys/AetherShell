# Evaluator latency and throughput, 2026-09-29

`examples/perf_probe.rs` (in-process, median of 7) and
`benches/agentic/startup.sh` (process start to exit, mean of 30), Debian on
WSL2, release builds. **Before** is `694cb9d`, built from a clean clone with
the same probe copied in; **after** is this commit. The two were run
interleaved, twice; the table averages the rounds.

| Case | Before | After | |
| --- | ---: | ---: | ---: |
| builtin call (`len([x])`, per call) | 577 ns | 216 ns | 2.7x |
| lambda `map` (per element) | 415 ns | 178 ns | 2.3x |
| `where` (per element) | 396 ns | 172 ns | 2.3x |
| build a record + `where(.n > 5)` | 1,644 ns | 500 ns | 3.3x |
| `str(x) + "-"` | 1,081 ns | 658 ns | 1.6x |
| sort (per element) | 336 ns | 158-237 ns | 1.4-2.1x |
| `sql` over piped rows (per row) | 982 ns | 744 ns | 1.3x |
| `ae -c 1`, process | 3.7 ms | 3.6-3.7 ms | -- |

## What changed, in the order the profiler found it

callgrind, not guesses: each step was the largest remaining cost.

1. **Every builtin call went to disk.** `journal::mark` listed the session
   directory whenever the journal was empty, and hashed the working
   directory to find it -- in every mode, on every call. Now only a call
   that can write consults the journal, and it loads once per directory.
2. **Three environment reads per call** (`journal::enabled` ->
   `current_mode` -> `truthy_env`) were 27% of a builtin call. They are only
   read for `WriteLocal`/`Destructive` calls now, and through `var_os`.
3. **Binding a lambda parameter was two thirds of `map`.** The variable
   table was a `BTreeMap<String, Value>` holding ~120 module entries, and a
   call inserts and removes its parameters: comparisons plus rebalancing per
   element. It is an `FxHashMap` now.
4. **Copies.** `map` and `where` cloned their whole input before starting,
   every element again for the lambda, and `where` each kept element a
   third time; `call_lambda` cloned any shadowed binding and the parameter
   name. Elements now move into the binding and back out
   (`call_lambda_owned`, `call_lambda_one`); a lambda body cannot rebind a
   parameter, so what comes back is what went in.
5. **Lookups per call:** `signature_of` did two linear scans of ~415
   declarations (~800 string compares for an undeclared builtin);
   `effect_of` ran a ~1,000-arm string match; `guard_dispatch` copied every
   string argument before learning the effect needed nothing. An index, a
   per-thread cache, and an early return for `Pure`/`ReadLocal`.

## What did not move, and why

**Startup.** After the changes `ae -c 1` executes about 2.9M instructions
(~1 ms); the rest of its ~3.6 ms is `exec`, the dynamic loader mapping and
relocating a 50 MB binary, and exit. Fat LTO with one codegen unit shrank
the binary to 39.5 MB and relocations from 53k to 33k, and startup did not
change measurably -- while adding ~6 minutes to every release build, so it
was not adopted. Freeing the environment at exit (14% of the instructions)
is skipped. For many calls, the answer remains a warm session
(`latency-warm.md`: 0.47 ms per `sql_value` over `ae mcp stdio`).
